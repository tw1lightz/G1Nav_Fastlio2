# G1 建图可视化链路与启动流程总结
# 0.fastlio2（ROS1）建图输出话题
你在容器中确认的输出：
- `/local_cloud`：点云（建图过程关键）
- `/velodyne_points`：点云（RViz配置默认用这个）
- `/slam_odom`：里程计
- `/global_path`：轨迹 Path
- `/tf、/tf_static`：TF
- `/ground_cloud`：地面点云（可选）
- `/loop_mark`：回环 marker（可选）
- `/projected_map`：2D 栅格地图（nav_msgs/OccupancyGrid） ← 你最终在 RViz2 用它看到 2D 图
## 1. 总体架构与数据链路

### 1.1 最终链路（从传感器到上位机可视化）
- **G1 本体 Docker（ROS1 Noetic）**
  - `livox_ros_driver2（ROS1）`：直接采集雷达与 IMU（绕过本体 ROS2）
  - `fastlio2`：建图节点发布 **点云 / 轨迹 / TF / 2D map（projected_map）**
- **G1 宿主机（ROS2 Foxy）**
  - `ros1_bridge dynamic_bridge`：将 ROS1 话题桥接到 ROS2 Foxy（DDS）
- **上位机（ROS2 Humble）**
  - `RViz2`：订阅 ROS2 话题，显示建图过程（PointCloud + Map + TF + Path）

## 3. G1 宿主机（ROS2 Foxy）配置与桥接

### 3.1 修正 CycloneDDS 配置

**配置文件路径：**
- `/home/unitree/cyclonedds_ws/cyclonedds.xml`

**配置内容：**
```xml
<?xml version="1.0" encoding="UTF-8" ?>
<CycloneDDS xmlns="https://cdds.io/config">
  <Domain Id="any">
    <General>
      <NetworkInterfaceAddress>eth0</NetworkInterfaceAddress>
      <AllowMulticast>spdp</AllowMulticast>
    </General>
  </Domain>
</CycloneDDS>
```

---

### 3.2 启动 ros1_bridge（强制“干净终端”）

> 必须在“干净终端”里启动，避免 ROS1/ROS2 环境混乱。

#### 3.2.1 开干净终端
```bash
exec bash -l
```

#### 3.2.2 Source 顺序（先 ROS1 再 ROS2）
```bash
source /opt/ros/noetic/setup.bash
source /opt/ros/foxy/setup.bash
```

#### 3.2.3 设置 DDS 相关环境变量
```bash
export RMW_IMPLEMENTATION=rmw_cyclonedds_cpp
export CYCLONEDDS_URI=/home/unitree/cyclonedds_ws/cyclonedds.xml
```

#### 3.2.4 ROS1 Master 与本机网络设置
```bash
export ROS_MASTER_URI=http://127.0.0.1:11311
export ROS_IP=$(hostname -I | awk '{print $1}')
```

- 容器是 **host 网络**，所以 ROS1 master 用本机 `11311`
- `ROS_IP` 建议使用 **G1 实际 IP**，避免只在本机可见的风险

#### 3.2.5 启动动态桥（桥接标准消息，自动桥 all topics）
```bash
ros2 run ros1_bridge dynamic_bridge --bridge-all-topics
```

> 注意：`dynamic_bridge` 是“按需桥接/按需回收”的。
> - 像 `/move_base_simple/goal`、`/initialpose` 这种“指令类 topic”通常只在点击 RViz 或命令行发布的一瞬间出现一次，发布结束后桥会被回收，日志里会看到类似：`removed 2to1 bridge for topic '/move_base_simple/goal'`。
> - 因此在 ROS2 侧 `ros2 topic list` 里看不到这些 topic 并不代表不可用；只要 ROS2 侧开始发布、ROS1 侧有订阅者，桥会自动创建。

#### 3.2.6 从 ROS2 给 ROS1 move_base 发目标（推荐做法）

**A. 固定桥接（不随 pub/sub 消失）**

如果你希望 `/move_base_simple/goal`、`/initialpose` 在 ROS2 侧长期可用，建议改用 `parameter_bridge` 固定桥接：
```bash
ros2 run ros1_bridge parameter_bridge \
  /move_base_simple/goal@geometry_msgs/msg/PoseStamped[geometry_msgs/PoseStamped] \
  /initialpose@geometry_msgs/msg/PoseWithCovarianceStamped[geometry_msgs/PoseWithCovarianceStamped]
```

**B. RViz2 的话题名差异（/goal_pose vs /move_base_simple/goal）**

RViz2 有的工具默认会发布 `/goal_pose`（而 ROS1 `move_base` 通常订阅的是 `/move_base_simple/goal`）。
如果你的 RViz2 只能发 `/goal_pose`，需要做一层“话题适配”：
- ROS2 订阅 `/goal_pose`（PoseStamped）
- 转发发布到 `/move_base_simple/goal`（PoseStamped）

（也可以直接用命令行在 ROS2 侧发布 `/move_base_simple/goal` 来验证桥接是否正常。）

## 5. 常见坑与对应解决

### 5.1 ros1_bridge 缺 `libroscpp.so`
- **原因：** 只 source 了 ROS2，没有 source ROS1
- **解法：** 干净终端里按顺序 source：**先 noetic 后 foxy**

---

### 5.2 CycloneDDS 报 XML 配置不认识 `Interfaces`
- **原因：** Foxy 的 CycloneDDS 版本偏老，不兼容新配置元素
- **解法：**
  - 改成 `NetworkInterfaceAddress` 的旧写法（推荐），或
  - 临时 `unset CYCLONEDDS_URI`（应急）

---

### 5.3 RViz2 只有点云，没有 2D 栅格
- **原因：**
  - 你加的是 `PointCloud2 / Path / TF`，但 **2D 栅格需要 RViz 的 Map 显示**
  - 而且话题名不是 `/map`，而是 `/projected_map`
- **解法：** `Add → Map → topic /projected_map`

---

### 5.4 `dynamic_bridge` 桥接太多话题
- **风险：** 增加 CPU / 带宽占用
- **后续优化：** 改用 `parameter_bridge` 只桥需要的（如果你要我也可以给你精确命令清单）
