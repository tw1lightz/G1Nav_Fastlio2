# HongTu 导航系统架构与技术栈笔记

> 基于 G1 人形机器人项目实际代码整理，适合有 ROS 基础但对导航/SLAM 不熟悉的开发者阅读。

---

## 一、项目在做什么（一句话概括）

用 Livox MID360 的 **LiDAR + IMU 融合里程计（FAST-LIO2 思路）** 得到机器人在地图中的位姿（重定位/里程计），同时加载一张 **2D 栅格地图**，把 3D 点云处理成 **2D LaserScan(/scan)** 给传统 2D 导航栈使用，最后由 **move_base + 代价地图 + 全局规划(GlobalPlanner) + 局部规划(TEB)** 输出 `cmd_vel` 速度指令，经 `velocity_smoother` 平滑后驱动底盘。

- 导航主入口：`G1Nav2D/src/fastlio2/launch/navigation.launch`
- 建图主入口：`G1Nav2D/src/fastlio2/launch/mapping.launch`

---

## 二、建图(mapping) 与导航(navigation) 的区别

| | 建图 (mapping.launch) | 导航 (navigation.launch) |
|---|---|---|
| 核心节点 | `map_builder_node` | `localizer_node` + `slam_reloc.py` |
| 配置文件 | `config/mapping.yaml` | `config/localize.yaml` |
| 目的 | 生成点云地图（PCD）和 2D 栅格 | 加载已有地图 → 重定位 → 路径规划 → 运动控制 |
| 可选组件 | `octomap_server`（3D 体素地图） | `map_server` + `move_base` + `velocity_smoother` |
| 输出 | .pcd 文件 + .pgm/.yaml 2D 地图 | /cmd_vel 速度指令 |

### 建图操作流程回顾
```bash
# 1. 启动建图
roslaunch fastlio mapping.launch

# 2. 保存 3D 点云地图
rosservice call /save_map "{save_path: '/root/HongTu/test2.pcd', resolution: 0.0}"

# 3. 保存 2D 栅格地图（同一建图会话）
rosrun map_server map_saver -f /root/HongTu/map/test2 map:=/projected_map
```

### 导航启动
```bash
roslaunch fastlio navigation.launch pcd_map:=/root/HongTu/test2.pcd map2d_yaml:=/root/HongTu/map/test2.yaml
```

## 三、从传感器到机器人走起来：三条主线

理解导航系统，脑子里同时画三条线：**数据流、TF流、控制流**。

### 3.1 数据流（传感器数据怎么变成规划能用的输入）

下面按 `navigation.launch` 里实际串联的顺序，列出每个关键环节：

#### ① Livox 驱动发布原始数据
- 节点：`livox_ros_driver2` 的 `msg_MID360.launch`
- 发布话题：
  - `/livox/lidar` (PointCloud2) — 3D 点云
  - `/livox/imu` (IMU) — 惯性测量单元数据
- 这是整个 SLAM/里程计的数据源头。

#### ② FAST-LIO2 系的 localizer 输出位姿/里程计
- 节点：`localizer_node`
- 配置：`fastlio2/config/localize.yaml`
- 订阅：`/livox/lidar`、`/livox/imu`
- 输出：`/slam_odom`（里程计）+ TF（`map -> local -> body`）

关键参数（localize.yaml）：
```yaml
lio_builder:
  det_range: 100.0         # 激光检测范围
  resolution: 0.2          # 体素分辨率
  min_point_range: 0.0     # 点云最小距离裁剪
  max_point_range: 25.0    # 点云最大距离裁剪
  align_gravity: true      # 重力对齐
  imu_ext_rot: [1,0,0, 0,1,0, 0,0,1]   # IMU 外参旋转
  imu_ext_pos: [-0.011, -0.02329, 0.04412]  # IMU 外参平移

localizer:
  refine_resolution: 0.2   # 精配准分辨率
  rough_resolution: 0.5    # 粗配准分辨率
  refine_iter: 5           # 精配准迭代次数
  rough_iter: 10           # 粗配准迭代次数
  thresh: 0.15             # 匹配阈值
  xy_offset: 2.0           # XY 搜索范围
  yaw_offset: 1.0          # 偏航搜索范围
```

#### ③ slam_reloc.py：PCD 地图重定位辅助
- 接收 `pcd_path` 参数（离线建好的 PCD 地图）
- 功能：拿当前局部点云去跟离线点云地图做**全局/局部匹配**，帮助把 `local` 坐标系对齐到 `map`
- 这决定了机器人"知道自己在地图哪里"的能力

#### ④ 2D 栅格地图由 map_server 发布
- launch 文件：`fastlio2/launch/gridmap_load.launch`
- 话题：`/map_2d`（注意是 remap 过的，不是默认的 /map）
- frame_id：`map`
- 这就是 move_base costmap 静态层的底图来源

#### ⑤ body2any_pointcloud：把点云变到 base_link 坐标系
- launch 文件：`tool/launch/body2any_pointcloud.launch`
- 输入：原始点云（body 坐标系下）
- 输出：`/base_link_cloud`（base_link 坐标系下的点云）
- 作用：统一后续处理的参考坐标系

#### ⑥ pointcloud_to_laserscan：3D 点云 → 2D 激光扫描
- launch 文件：`pointcloud_to_laserscan/launch/point_to_scan.launch`
- 输入：`/base_link_cloud`
- 输出：`/scan` (LaserScan)
- 关键参数：
```yaml
min_height: -1       # 截取高度下限（米，base_link 坐标系）
max_height: 0.15     # 截取高度上限
range_min: 0.2       # 最小有效距离
range_max: 100       # 最大有效距离
angle_increment: 0.007  # 角分辨率（弧度）
```

> **工程关键理解**：move_base 最喜欢的世界是"2D 栅格地图 + 2D 激光(/scan) + odom"。你的系统用 3D LiDAR + LIO，但最终还是"适配回传统 2D 导航栈"。

#### 完整数据流图
```
/livox/lidar ──┬──→ localizer_node ──→ /slam_odom (里程计)
               │                   └──→ TF: map→local→body
/livox/imu  ───┘
               │
               └──→ body2any_pointcloud ──→ /base_link_cloud
                                                   │
                                        pointcloud_to_laserscan
                                                   │
                                                   ▼
                                                /scan (LaserScan)
                                                   │
map_server ── /map_2d                              │
      │                                            │
      └─────────────→ move_base ←──────────────────┘
                          │
                       /cmd_vel
                          │
                   velocity_smoother
                          │
                       底盘驱动
```

### 3.2 TF 流（坐标系怎么串起来）

> **导航是否稳定，80% 的问题最后都会落到 TF。**

#### 本项目涉及的坐标系

| Frame | 含义 | 谁发布 |
|-------|------|--------|
| `map` | 全局地图坐标（静态、绝对） | localizer + slam_reloc |
| `local` | LIO 的局部连续坐标（类似 odom，会漂移） | localizer_node |
| `body` | FAST-LIO 内部的机体坐标 | localizer_node |
| `base_link` | 导航/代价地图用的机器人基座坐标 | static_transform (body→base_link) |
| `top_laser_link` | 顶部激光传感器坐标（costmap 中引用） | 需确认是否有发布 |

#### 核心 TF 链路
```
map ──(重定位)──→ local ──(LIO 里程计)──→ body ──(静态 TF, roll=180°)──→ base_link
```

move_base **硬性要求** `map -> base_link` 这条 TF 链路是连通且实时更新的。断了 = 导航直接废掉。

#### 静态 TF（navigation.launch 里显式定义）
```xml
<node pkg="tf" type="static_transform_publisher" name="base_to_body"
      args="0 0 0 0 0 3.1416 /body /base_link 10" />
```
- `body → base_link`，roll = π（180°）
- 原因：MID360 传感器**倒装**在 G1 头部，需要翻转 180° 修正
- 如果这个 TF 设错：点云倒置，/scan 方向异常，规划碰撞判断全错，里程计发散

### 3.3 控制流（move_base 如何从目标点输出速度）

#### move_base 的输入/输出
- **输入**：
  - 当前位姿：来自 TF（map→base_link）+ odom（remap 到 `slam_odom`）
  - 全局地图：`/map_2d`
  - 障碍物观测：`/scan`（LaserScan）
  - 导航目标：`/move_base/goal` 或通过 actionlib
- **输出**：
  - `/cmd_vel`（Twist 消息，线速度+角速度）

#### move_base 参数文件清单
| 文件 | 内容 |
|------|------|
| `movebase/param/costmap_params.yaml` | 全局/局部代价地图配置 |
| `movebase/param/move_base_params.yaml` | move_base 框架参数 |
| `movebase/param/teb_local_planner_params.yaml` | TEB 局部规划器参数 |
| `movebase/param/costmap_converter_params.yaml` | 代价地图转换器参数 |

## 四、10 个导航核心概念详解

### 4.1 SLAM（同步定位与建图）
- **全称**：Simultaneous Localization and Mapping
- **本质问题**：机器人一边走一边回答"我在哪"（定位）和"周围长什么样"（建图）
- **本项目用的**：FAST-LIO2 思路，属于 **LiDAR-Inertial Odometry (LIO)**
  - 激光点云 + IMU 紧耦合，用迭代卡尔曼滤波做状态估计
  - 建图时逐帧拼接点云
  - 导航时用已有地图做匹配定位（重定位/relocalization）

### 4.2 里程计 (Odometry)
- **含义**：机器人相对于起点走了多远、转了多少
- **本项目**：LIO 输出 `/slam_odom`，包含位置 + 姿态 + 速度
- **与 TF 的关系**：里程计本质上就是 `local -> body` 的变换
- **关键特性**：连续、平滑，但会**累积漂移**（越走越不准）——所以需要重定位来修正

### 4.3 重定位 (Relocalization)
- **含义**：把当前位姿"校正"到全局地图坐标系
- **本项目**：`slam_reloc.py` + `localizer` 的 localizer 参数
  - 粗配准（rough）：大范围搜索，分辨率 0.5m
  - 精配准（refine）：小范围优化，分辨率 0.2m
- **类比**：你迷路了，拿出地图，看周围地标，确定自己在哪个位置——这就是重定位

### 4.4 点云 (Point Cloud)
- **含义**：3D 空间中一堆点的集合，每个点有 (x, y, z) 坐标，可能还有反射强度等
- **本项目**：Livox MID360 发布 `/livox/lidar` (PointCloud2 格式)
- **处理链**：原始点云 → body2any（坐标变换）→ pointcloud_to_laserscan（降维为 2D）
- **PCD 文件**：点云的离线存储格式（`.pcd`），你建好的 3D 地图就是 PCD

### 4.5 2D 栅格地图 (Occupancy Grid Map)
- **含义**：把环境切成网格，每个格子标记"占据（墙/障碍）"、"空闲（可通行）"、"未知"
- **文件格式**：`.pgm`（图片）+ `.yaml`（元信息：分辨率、原点、阈值）
- **本项目**：由 `map_server` 加载 `.yaml`，发布到 `/map_2d` 话题
- **分辨率**：你的 costmap 配置里 `resolution: 0.05`，即每格 5cm

### 4.6 代价地图 (Costmap)
- **含义**：在栅格地图基础上，给每个格子赋一个"通行代价"值（0=空闲，254=致命障碍，中间=不同程度的危险）
- **本项目有两张代价地图**：
  - **global_costmap**：覆盖整个地图，用于全局路径规划
  - **local_costmap**：机器人周围的滑动窗口（3m×3m），用于局部避障
- **三层叠加**（global_costmap 为例）：

```
┌─────────────────────────────────────────┐
│ StaticLayer:  来自 /map_2d 的静态地图     │
├─────────────────────────────────────────┤
│ ObstacleLayer: /scan 实时观测到的障碍物   │
├─────────────────────────────────────────┤
│ InflationLayer: 把障碍物向外膨胀          │
│   给机器人留安全距离                      │
└─────────────────────────────────────────┘
```

关键参数（costmap_params.yaml）：
```yaml
# 机器人足迹（多边形，单位米）
footprint: [[0.3, 0.15], [0.25, 0.2], [-0.1, 0.2], [-0.1, -0.2], [0.25, -0.2], [0.3, -0.15]]

# 膨胀参数
inflation_layer:
  inflation_radius: 20      # global：膨胀半径（格数 × 分辨率）
  cost_scaling_factor: 9    # 代价随距离衰减的速度

# 障碍物观测源
obstacle_layer:
  observation_sources: 3dscan 2dscan
  2dscan: { topic: scan, obstacle_range: 3.0, raytrace_range: 3.5 }
```

### 4.7 全局规划 (Global Planning)
- **算法**：`global_planner/GlobalPlanner`（基于 Dijkstra 或 A* 的栅格搜索）
- **输入**：global_costmap + 起点 + 目标点
- **输出**：从起点到目标的完整路径（一串 waypoint）
- **调用频率**：`planner_frequency: 1.0`（每秒重规划一次）
- **特点**：只管"大方向绕墙"，不管动力学约束和速度

### 4.8 局部规划 (Local Planning) — TEB
- **全称**：Timed Elastic Band
- **直觉理解**：把全局路径的一小段"拉成橡皮筋"，然后用优化算法调整，同时满足：
  - 不撞障碍物
  - 速度/加速度在限制内
  - 尽量快到达
  - 尽量平滑
- **本项目关键参数**（teb_local_planner_params.yaml）：
```yaml
# 速度限制
max_vel_x: 1.0        # 最大前进速度 m/s
max_vel_theta: 0.7     # 最大转弯角速度 rad/s
acc_lim_x: 0.8         # 最大前进加速度

# 目标到达容差
xy_goal_tolerance: 0.5    # 位置容差（米）
yaw_goal_tolerance: 0.35  # 角度容差（弧度）

# 障碍物
min_obstacle_dist: 0.2    # 最小障碍物距离
inflation_dist: 0.6       # 膨胀距离

# 同伦类规划（尝试多条拓扑不同的绕行路径）
enable_homotopy_class_planning: True
max_number_classes: 4
```

### 4.9 TF 树 (Transform Tree)
- **含义**：ROS 的坐标变换体系，描述所有坐标系之间的空间关系
- **move_base 硬性要求**：`map -> base_link` 必须连通且实时
- **本项目的 TF 链**：
  ```
  map → local → body → base_link
  ```
- **调试命令**：
  ```bash
  rosrun tf view_frames     # 生成 TF 树 PDF
  rosrun tf tf_echo map base_link  # 实时打印变换
  ```

### 4.10 速度平滑 (Velocity Smoother)
- **为什么需要**：TEB 输出的 cmd_vel 可能有突变（方向急转、速度跳变），直接发给底盘会导致机器人抖动、打滑
- **本项目**：`velocity_smoother_ema`（指数移动平均平滑器）
- **放在**：move_base 的 cmd_vel 输出之后、底盘驱动之前

## 六、调试检查顺序（导航工程常用）

按优先级排序，出问题时从上往下排查：

| 优先级 | 检查项 | 命令/方法 | 常见问题 |
|--------|--------|-----------|----------|
| 1 | TF 链路 | `rosrun tf tf_echo map base_link` | 断裂 → move_base 完全不工作 |
| 2 | /map_2d 话题 | `rostopic echo /map_2d -n1` | 未发布 / frame_id 不是 map |
| 3 | /scan 数据 | `rostopic hz /scan` + RViz 可视化 | 无数据 → 检查 min_height/max_height |
| 4 | slam_odom 里程计 | `rostopic echo /slam_odom` | 方向反、时间戳异常、发散 |
| 5 | costmap 障碍物标记 | RViz 查看 costmap 层 | 障碍未标记/未清除 |
| 6 | TEB 速度输出 | `rostopic echo /cmd_vel` | 速度限制不匹配底盘能力 |
| 7 | 重定位状态 | `rosservice call /slam_reloc_check` | 未收敛 / 位姿跳变 |

## 七、排障速查

| 现象 | 检查点 |
|------|--------|
| 点云倒置 | `rostopic echo /livox/imu` 检查 z 轴加速度方向；检查 body→base_link 的 static TF |
| TF 断裂 | RViz 查看 `map → local → body → base_link` 链路是否完整 |
| /scan 无数据 | 检查 `point_to_scan.launch` 的 `min_height/max_height` 是否切到合理高度 |
| 重定位无响应 | `rosservice call /slam_reloc_check` 验证；检查 PCD 路径是否正确 |
| 机器人不动 | 检查 cmd_vel 是否有输出；检查 velocity_smoother 是否吞掉了指令 |
| 导航绕路/撞墙 | 检查 costmap 膨胀参数；检查 footprint 是否与实际机器人尺寸匹配 |
| 局部规划震荡 | 调整 TEB 的 `oscillation_recovery` 参数和 `min_obstacle_dist` |

## 八、参数调优建议（当前配置可能的问题点）

1. **local_costmap 只启用了 inflation_layer**：plugin 列表里没有 obstacle_layer，意味着局部代价地图不会实时插入障碍物，仅靠膨胀层。动态避障能力可能不足。
2. **global costmap 的 inflation_radius: 20**：这是 20 格 × 0.05m = 1m 的膨胀半径，如果过大可能导致窄通道无法通过。
3. **TEB max_vel_x: 1.0**：对于人形机器人来说可能偏快，需要根据实际底盘能力调整。
4. **xy_goal_tolerance: 0.5**：目标容差半米，对精准导航场景（如电梯口停靠）可能偏大。
5. **costmap 中引用了 `vlp_points` 和 `top_laser_link`**：确认链路中是否真的有这个话题和 TF，否则该观测源实际不生效。
